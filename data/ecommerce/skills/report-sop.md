# 分析报告 SOP

> 适用：用户说"整理成报告""出一份报告""把这次分析汇总一下"。
> 前提：本会话里已有分析（查数/归因）。报告是**搬运 + 结构化**，不是重新查数。

## 报告四段（用户视图，顺序固定）

### 一、问题
- 一句话说清这次分析要回答什么，并写清条件：时间窗用**绝对日期** `[开始, 结束)`，口径名称
- 紧跟一行：`数据截止时间: YYYY-MM-DD`（取自材料包的"数据覆盖"）

### 二、数据及结果
- 照抄会话里已查得的关键数字，每个数字挂它**真实来源**的 (Qn)
- 派生数（差额/降幅/占比/净贡献/单均/闭合/LMDI 乘法归因）**必须先用 `calculate` 工具算**，再引用它给的 Qn；禁止心算

### 三、原因
- 只搬运会话里**已经讨论过**的原因/假设
- 没有实锤的必须写"**待验证**"；禁止把"可能"升级成"就是"，禁止加入会话里没说过的新假设

### 四、改进建议
- 基于会话结论给可操作的下一步（如"查直通车预算变动""查详情页转化"）

## 引用与公式

- 每个数字后写 `(Qn)`；Qn 是会话级连续编号，直接写，**不要**写"本轮/首轮"
- 派生数用 `calculate` 的具名公式（当前可用）：
  `delta{curr,prev}` 差额 ｜ `pct_change{curr,prev}` 降幅% ｜ `share{part,total}` 占比% ｜
  `contribution{part_delta,net_delta}` 净贡献% ｜ `avg{total,count}` 平均 ｜ `closure{parts,total}` 闭合差 ｜
  `lmdi{total_curr,total_prev,factors}` 乘法关系的 LMDI 因素贡献（自动对账，逐因素按 `curr/prev` 传入）
- 基期为 0 / 分母为 0 时**不适用**，如实写"不适用"，禁止无穷大

## 落盘

- 定稿后调 `save_report(title, content)`
  - `content` = 报告四段正文（含 (Qn) 引用），**不要**包含证据明细
  - 工具会**对账**：每个数字必须能在所引 Qn 的账本记录里找到；返回 `rejected` + `issues` 时，按 issues 修正后重新调用
- 工具返回 `saved` + Word 路径

## 最终答复骨架

```
报告四段正文（用户可直接复制）
###EVIDENCE###
证据明细：每个 Qn 的 SQL 事实 + 计算式 + 口径说明
```
