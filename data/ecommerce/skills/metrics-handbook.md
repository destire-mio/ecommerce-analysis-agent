# 经营指标手册（方法篇）

> 指标的**定义、公式、口径、单位**已全部移入语义层 `mdl.yaml`（唯一权威，
> 由 `tools/gen_mdl_docs.py` 生成人读版 `语义层说明.md`）。本卡不再重复口径，
> 只保留：指标关系、拆解方法、数据源分工、易错坑。

## §0 指标关系树（归因的骨架）

```
GMV(商品支付金额) = 访客数 × 转化率 × 每单平均金额
     │                │        │         │
   语义层           平台MCP    语义层     语义层
 (query_metrics) (get_shop_traffic) (query_metrics) (query_metrics)
```

任何 GMV 变化都可以拆到这三个因素上；每个因素的下一层拆解刀见下文。

## §1 数据源分工

- **自店交易数据**（金额/订单数/单均/品类/商品）：语义层标准指标，用 `query_metrics` 查，**不要自己写聚合 SQL**
- **平台侧数据**（访客/大盘/漏斗）：语义层够不到，必须用 MCP 工具
  - `get_shop_traffic(start, end[, source])` —— 渠道流量
  - `get_market_overview(start, end, industry)` —— 行业大盘
  - `get_funnel(start, end)` —— 转化漏斗

## §2 拆解刀

- **渠道刀**：get_shop_traffic 两期各渠道，找"断流渠道"（大幅下降且体量大 = 首要嫌疑）
- **日期刀**：突降 = 事件性；渐降 = 趋势性
- **大盘刀**：get_market_overview 对照行业增速——我店降幅 >> 大盘 = 独立问题；接近 = 行业性波动
- **品类刀**：按 category 分组（query_metrics dimensions=["category"]）
- **漏斗刀**：get_funnel 五节点，找与上期相比降幅最大的节点
  （加购→支付塌 = "临门一脚"；详情页→加购塌 = "意愿"）

- **坑**：先看结构再看总量——总访客平稳但结构变化（付费塌、免费涨）同样重要；
  整体转化率下降可能不是"转化变差"，而是低转化渠道占比上升（结构效应）。

## §3 行为红线（MDL 挡不住、必须自觉的）

1. **跨品类订单数不可相加**：一张订单可跨两个品类，品类订单数之和 > 店铺去重订单数——
   这是正确行为，但**禁止把品类订单数相加当成店铺订单数**。
2. **比率不可直接相加/平均**：两天的转化率 ≠ 两天转化率的平均；
   正确做法是 SUM(分子) ÷ SUM(分母)（或让引擎先聚合再除）。
3. **基期为 0**：环比/占比标"不适用"，展示差额，禁止输出无穷大。
4. **未开放指标禁止给数字**：退款率/库存/利润/复购率——禁止任何计算、推断或编数；
   利润**禁止从销售额推导**。
5. **未开放的数据维度**：漏斗更细分层、竞品、活动日历、库存快照——
   如实回答"该数据维度未接入"，列为待验证假设。

## §4 证据等级（归因结论必须分层）

1. **观测事实**：两期数字与变化（确定）
2. **数学贡献**：某因素贡献多少（确定性计算，需闭合）
3. **业务假设**：为什么——没有证据就是假设，措辞必须"可能/待验证"，禁止说成结论
