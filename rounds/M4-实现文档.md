## 2. LMDI 数学（照抄，别自由发挥）

设总量 X，因素 f1..fk（乘法关系 X = f1×f2×…×fk），基期 0 / 本期 1：

```
对数均值权:  w = (X₁ - X₀) / ln(X₁ / X₀)          ← X₀,X₁>0 才成立
因素贡献:    Δfᵢ = w · ln(fᵢ₁ / fᵢ₀)
铁性质:      ΣΔfᵢ = w · ln(X₁/X₀) = X₁ - X₀        ← 精确闭合，与顺序无关
```

**本店真数（验收断言用）**：

```
基期(前7天):  GMV=1000000  访客=98975   转化率=0.10103561505430664  单均=100.0
本期(近7天):  GMV=800000   访客=110596  转化率=0.0723353466671489   单均=100.0

ΔGMV        = -200000
w           = 896284.023545
访客贡献     = +99502.4310
转化率贡献   = -299502.4310
客单价贡献   = 0.0
闭合(Σ-Δ)    ≈ 5.8e-11      ← 浮点误差量级，断言用 abs(...) < 1e-3
重建校验     = 0 相对误差（转化率/单均与GMV同源，恒等式精确成立）
```

**验证公式**：`访客×转化率×单均`：98975×0.10103561505430664×100=1000000 ✓；110596×0.0723353466671489×100=800000 ✓

## 3. 零值规则（D3，逐条实现）

| 情形 | 处理 | 返回 |
|---|---|---|
| `X₀==0 or X₁==0` | 整体不适用 | `{"status":"undefined","reason":"总量含0, 乘法分解不适用","total_delta":...}` |
| 某因素 `fᵢ₀==0 or fᵢ₁==0` | 该因素贡献 = `None`；**其余因素照常分解**；`residual = ΔX - Σ(其余贡献)`；\|residual\| > \|ΔX\|×0.5 时附警告 | `contributions[fᵢ]=None, residual=..., warnings=[...]` |
| 某因素 `fᵢ₁==fᵢ₀`（比=1） | 正常给 `0.0` | 无需特判 |
| `X₀<0 or X₁<0` | 不适用（log 无定义，本项目不会出现负值总量） | undefined |

**铁律**：0 因素的贡献**就是不给数**（`None`），绝不编 0；残差是"已算部分与总量的差"（可复核），不是编造。

## 4. 恒等式 / 对账（mdl.yaml 声明 + 自动触发）

### 4.1 mdl.yaml 新增（结构化，不搞表达式解析器）

```yaml
identities:            # 严格恒等: 各因素乘积 == 总量, 容差 0
  - name: GMV乘法恒等
    type: derived_identity
    total: GMV
    factors: [访客数, 转化率, 单均金额]
    tolerance: 0.0
reconciliations:       # 近似对账: 口径可能不同, 容差 2%
  - name: GMV口径对账
    type: reconciliation_rule
    total: GMV
    factors: [访客数, 转化率, 单均金额]
    tolerance: 0.02
    note: 平台转化率口径若为"买家UV"而非订单口径, 乘积与GMV可能有差
```

### 4.2 自动触发（Q-a）

`lmdi` 算完后自动做：`重建 = Π(因素本期值)`，`相对误差 = |重建 - 总量本期| / |总量本期|`。
- 若相对误差 > tolerance（默认 0.02）→ 结果里带：
  ```json
  "reconciliation": {"reconstructed": ..., "actual": ..., "rel_error": ...,
                     "tolerance": 0.02, "warning": "重建总量与实测偏差超过容差, 口径可能不一致"}
  ```
- 未超差 → `reconciliation` 里 `ok: true`。
- **警告不拒绝**：正常返回分解结果，只是多一个 warning。

### 4.3 容差来源

`formulas.lmdi(..., tolerance=0.02)` 默认 0.02；`agent_loop.calculate` 的 lmdi 分支从 registry 读 `reconciliations` 里对应规则（无则默认 0.02）传入。**formulas.py 保持纯函数（不读文件）**。

## 5. 实现步骤（按顺序，每步可单独验证）

### 步骤 1 · `semantic/formulas.py`（新建，纯函数）

```python
import math

def lmdi(total_curr, total_prev, factors: dict, tolerance: float = 0.02) -> dict:
    """乘法关系 LMDI 加法分解。
    factors: {"因素名": {"curr": x, "prev": y}, ...}
    返回: status/contributions/shares/closure/residual/warnings/reconciliation
    """
```
要求：
- 总量 0/负 → `status="undefined"`
- 逐因素：任一为 0 → 该因素 `None`；否则 `w*ln(curr/prev)`
- `w = (total_curr-total_prev)/ln(total_curr/total_prev)`
- `closure = Σ(非None贡献) + 0*None数 - (total_curr-total_prev)`；有 None 时改为算 `residual = ΔX - Σ(非None)`
- `shares = 贡献/ΔX*100`（ΔX=0 时不适用）
- 自动重建校验 → `reconciliation`
- `warnings`：含 None 且 |residual|>0.5*|ΔX| 时加一条
