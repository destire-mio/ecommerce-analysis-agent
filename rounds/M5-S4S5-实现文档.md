# S4 · 图表（ECharts 配置）

## 定案（已讨论）
- **单独工具 `chart`**（不并进 query_metrics）
- 支持 **bar / line / pie** 三种
- 输出 ECharts option **JSON** 落盘 `reports/<id>.chart.json`；**不引 matplotlib**
- 图表文件等 M6 全栈 UI 时渲染到用户屏幕
- 取数的数字**同时进账本（Qn）**

## 实现
1. `semantic/chart.py`（新建，纯函数）：`to_echarts(columns, rows, chart_type, x, y) -> dict`
   - bar/line：`xAxis.data = [行的 x 列值]`，`series=[{type, data:[行的 y 列值]}]`
   - pie：`series=[{type:"pie", data:[{name:x值, value:y值}]}]`
2. `agent_loop.py`：
   - 新工具 `chart(spec, chart_type, x, y)`：
     - 用现有 `run_query_metrics(spec, db_path, mcp_bridge)` 取数
     - 校验 `x` 在 columns、`y` 在 columns（metric 列）
     - `to_echarts(...)` → 落盘 `reports/<逐字时间戳>.chart.json` → 返回 `{status, path, option, n_rows, columns}`
   - 工具 schema + 材料包提示：“要图时用 chart(基于 query_metrics 的 spec)”
   - 账本：chart 内部取数走 query_metrics，Qn 自然记账；chart 工具本身也进 trace
3. 图表类型白名单：`bar|line|pie`；其它 → `{"error":"unknown_chart_type"}`

## 验收：`tools/run_chart_acceptance.py`（新建）
- `{metrics:[GMV], dimensions:[category], time_range:近7天}` + bar/x=category/y=GMV
  → option `series[0].type=="bar"`、`xAxis.data` 含 "家电"/"其他行业"、`series[0].data` 含 350000/450000、文件已生成
- line 同理；pie 断言 `series[0].type=="pie"` 且 `data` 有 name/value
- 不回归：`tools/run_semantic_acceptance.py` 11/11

# S5 · 报告（窄：口径自动生成 + 对账加一层）

## 定案（已讨论）
- **窄目标**：只补两件，不做图文/美化/模板（那些进 todo 后续优化）
- ① **口径说明自动生成**：`save_report` 落盘时，按报告所引 Qn 中用到的**已登记指标**，从 mdl.yaml 生成"口径说明"节附在报告末尾，标注"由语义层生成"

   - 生成"## 口径说明（由语义层生成）"节，追加到 docx 正文末尾（`_write_docx`）
   - 用户视图正文（`content`）不含该节（工具自动附）
2. `data/ecommerce/skills/report-sop.md`：更新——说明"口径说明由工具自动附，正文不必手写口径"
3. 不改现有 `check_report` 的数字↔Qn 逻辑（本任务只加"口径节"）
