## 0. 目标与范围

**目标**：S3（口径解释）从"能说算法"升级到"能说算法 + 负责人 + 版本 + 生效时间"，并让口径**变更受控**。

**范围（一个闭环，全放本任务）**：
1. **读**：指标口径带 owner / version / effective_date / change_log，agent 能答
2. **提**：agent 可用工具**提议**改口径（写草稿，不碰权威文件）
3. **批**：人跑脚本**审批**后生效（改 mdl.yaml：升版本 + 追加记录）
4. **校验**：加载期机器校验变更记录一致

**明确不做（留 M7）**：按历史日期用旧版口径查询（temporal）、血缘/影响分析、多版本并存。

**为什么**：PRD L01 要求口径含定义/版本/负责人/生效时间/单位；badcase 已记 owner 缺口。且口径会低频修订，需要受控变更而非散落（`approved_sql.json` 漂移是反例）。

## 1. 设计定案（已讨论锁定）

| 项 | 定案 |
|---|---|
| 版本粒度 | **每个指标独立**版本 |
| 字段 | 每个 metric 增 `version / owner / effective_date / change_log` |
| 权威文件 | `mdl.yaml` **只有人改** |
| agent 权限 | **只能提议**（写草稿），**不能批准、不能直接改 mdl.yaml** |
| 草稿区 | `data/ecommerce/metric_changes/<id>.json` |
| agent 可见草稿 | ✅ 材料包提示"有变更待审批" |
| 审批 | 人跑脚本 `tools/approve_metric_change.py` |
| 校验 | change_log 版本连续、末条==当前 version；草稿 `old` 必须等于当前值 |

## 3. 实现步骤

### 步骤 1 · mdl.yaml 加字段（全部现有指标）
给 `GMV / 支付订单数 / 订单数订单粒度 / 访客数 / 单均金额 / 转化率` 及 measures 对应 metric 补 `owner/version:1/effective_date/change_log`（演示值即可）。

### 步骤 2 · `semantic/registry.py`
- metric 校验：要求 `owner/version/effective_date/change_log`
- **变更记录一致性校验**：change_log 的 version 必须从 1 连续递增，且最后一条 == `version`；每条须有 date/by/note；不满足 → `RegistryError`
- `describe()`：指标行带出 `owner/version/effective_date`

- 该工具**不**需要门禁写权限（它只写草稿区）；但**不能**有 approve 工具

### 步骤 4 · 审批脚本 `tools/approve_metric_change.py`（人跑）
```
用法: .venv/bin/python tools/approve_metric_change.py <id> [--reject]
- 读草稿; 校验 draft.old == mdl.yaml 当前该字段值(防基于过期版本改动)
- 批准: 改 mdl.yaml → version+1, effective_date=今天, append change_log{version,date,by,note=reason}
- 草稿 status → approved/rejected
- 校验通过后重载 registry(自检)
```

### 4.2 新增 `tools/run_s3_acceptance.py`
- **读**：`registry.describe()` 含 `owner`/`version`/`effective_date`
- **校验**：构造 change_log 断裂（如 version=1 但 changelog 末条 version=2）→ `RegistryError`
- **提**：调 `propose(...)` → 草稿文件生成、status=pending、**mdl.yaml 未变**（比对哈希）
- **批**：`approve` 后 → mdl.yaml `version==2`、effective_date 更新、change_log 追加一条；草稿 status=approved
- **防过期**：草稿 `old` 与当前值不符 → approve 拒绝并报错
